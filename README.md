# Учет компьютерной техники

Клиент-серверный модуль для ведения БД компьютерной техники.

- **Сервер:** .NET 10, ASP.NET Core Minimal API, EF Core 10 + Npgsql.
- **Клиент:** DevExtreme 25.2 для jQuery (тонкий клиент, раздается сервером из `wwwroot`).
- **СУБД:** PostgreSQL 18.

## Запуск

### Вариант 1. Docker (одной командой)

```bash
docker compose up --build
```

Откройте http://localhost:8080. Поднимутся PostgreSQL 18 и сервер. При старте сервер применяет миграции и заполняет начальные данные.

### Вариант 2. Локально (Visual Studio / dotnet CLI)

1. Нужен PostgreSQL 18. Проще всего поднять только БД: `docker compose up db`.
   Если БД своя — поправьте строку подключения `ConnectionStrings:Default` в `appsettings.json`.
2. Запустите проект `ComputerEquipment.Api` (профиль `http`) или выполните:

   ```bash
   dotnet run --project src/ComputerEquipment.Api
   ```

3. Откройте http://localhost:5080.

## Миграции

Схема БД описана миграциями EF Core в `src/ComputerEquipment.Api/Data/Migrations`. При старте сервер вызывает `Database.MigrateAsync()`: создает БД, если ее нет, и применяет новые миграции. Вручную ничего запускать не нужно.

Для работы с миграциями в репозитории есть локальный инструмент `dotnet-ef`:

```bash
dotnet tool restore

# добавить миграцию после изменения модели
dotnet ef migrations add <Имя> --project src/ComputerEquipment.Api --output-dir Data/Migrations

# применить миграции без запуска сервера
dotnet ef database update --project src/ComputerEquipment.Api

# получить SQL-скрипт всех миграций (например, для DBA)
dotnet ef migrations script --idempotent --project src/ComputerEquipment.Api -o schema.sql
```

В Visual Studio то же самое делается из Package Manager Console: `Add-Migration`, `Update-Database` (нужен пакет `Microsoft.EntityFrameworkCore.Tools`).

## Что реализовано

### Данные

| Поле | Ограничения |
|---|---|
| Учетный номер | цифры и латинские буквы, до 32 символов, **уникален** |
| Наименование | любые символы, до 256 |
| Тип техники | выбор из словаря `equipment_types` (ID, Наименование до 128 символов) |
| Комната размещения | целое число от 1 до 1000 |

Ограничения проверяются в трех местах: на клиенте (подсказки в форме), на сервере (ответ 400 с ошибками по полям) и в самой БД (уникальный индекс, CHECK-ограничения, внешний ключ).

Учетный номер приводится к верхнему регистру: `pc01` и `PC01` считаются одним номером.

### Начальные данные

При старте сервера:
- если словарь типов пуст — добавляются 5 типов: системный блок, ноутбук, монитор, принтер, сетевое оборудование;
- если таблица техники пуста — добавляются 50 демо-записей (по 10 на каждый тип — хватает на несколько страниц таблицы).

Заполнение идет под advisory-блокировкой, поэтому два одновременно стартовавших экземпляра не создадут дубли.

### Интерфейс

- **Каталог** слева: типы техники с количеством единиц. Щелчок по типу фильтрует таблицу. Здесь же можно добавить новый тип или удалить пустой.
- **Таблица**: колонки «Учетный номер», «Тип техники», «Наименование», «Комната размещения». Сортировка по всем колонкам (в том числе по нескольким сразу — с Shift), пагинация. Сортировка и пагинация выполняются **на сервере**.
- **Фильтр по типу** в панели таблицы (синхронизирован с каталогом) и поиск по номеру или наименованию.
- **Создание** — кнопка «Добавить технику», открывает диалог.
- **Редактирование** — все три способа: кнопка в строке, контекстное меню (правая кнопка мыши) и двойной щелчок.
- Удаление записи с подтверждением.
- Счетчик «Записей: N из 2000» в шапке; при достижении лимита кнопка добавления блокируется.

### Одновременная работа пользователей

1. **Один и тот же учетный номер.** Уникальный индекс `ix_equipment_inventory_number`. Сервер не проверяет «есть ли такой номер» заранее (между проверкой и вставкой другой пользователь может успеть сохранить тот же номер), а ловит нарушение уникальности от PostgreSQL (код `23505`) и возвращает `409 Conflict`. Пользователь видит сообщение в диалоге.
2. **Одновременное редактирование одной записи.** Оптимистичная блокировка по системному столбцу `xmin`. Клиент передает версию, которую видел при открытии диалога; если запись за это время изменили, сервер вернет `409` и попросит открыть карточку заново.
3. **Лимит 2000 записей.** Подсчет и вставка выполняются в одной транзакции под `pg_advisory_xact_lock`, поэтому параллельные запросы не превысят лимит. Лимит задается в `appsettings.json` → `Equipment:MaxRecords`.
4. Повторное нажатие «Сохранить» блокируется, пока идет запрос.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/catalog` | типы с количеством, общее число записей, лимит |
| GET | `/api/equipment?skip=&take=&sort=&typeId=&search=` | страница списка → `{ data, totalCount }` |
| GET | `/api/equipment/{id}` | одна запись |
| POST | `/api/equipment` | создание |
| PUT | `/api/equipment/{id}` | изменение (нужен `version`) |
| DELETE | `/api/equipment/{id}` | удаление |
| GET | `/api/equipment-types` | словарь типов |
| POST | `/api/equipment-types` | новый тип |
| DELETE | `/api/equipment-types/{id}` | удаление типа без техники |

`sort` — JSON-массив в формате DevExtreme: `[{"selector":"typeName","desc":true}]`. Допустимые поля: `inventoryNumber`, `typeName`, `name`, `room`. Размер страницы — до 100.

Ошибки возвращаются в формате ProblemDetails (RFC 9457); у конфликтов есть поле `code`: `duplicate`, `concurrency`, `limit`, `in-use`.

Примеры запросов — в `src/ComputerEquipment.Api/ComputerEquipment.Api.http`.

## Тесты

Юнит-тесты лежат в `tests/ComputerEquipment.Api.Tests` (xUnit). База данных и Docker для них не нужны.

```bash
dotnet test
```

В Visual Studio: «Тест» → «Обозреватель тестов» → «Выполнить все».

Что проверяется:

| Класс тестов | Что покрывает |
|---|---|
| `EquipmentRulesTests` | нормализация и валидация: формат и длина учетного номера, длина наименования, диапазон комнаты, обязательность версии при изменении |
| `EquipmentQueryTests` | разбор параметра `sort` от DevExtreme, сортировка по каждой колонке и по нескольким сразу, стабильный порядок при равных значениях, пагинация, экранирование поиска |
| `ProblemsTests` | распознавание ошибок PostgreSQL (дубль номера `23505`, внешний ключ `23503`) и ответы 400/404/409 |
| `AppDbContextModelTests` | модель EF Core: уникальные индексы, `xmin` как маркер версии, CHECK-ограничения, запрет удаления используемого типа и **соответствие миграций модели** |
| `SeedDataTests` | начальные данные: 3–5 типов, 50 записей, уникальные номера, все записи проходят валидацию |

Логика сортировки и пагинации вынесена в `Endpoints/EquipmentQuery.cs`, поэтому тесты выполняют ее на обычных коллекциях без базы.

## Структура

```
src/ComputerEquipment.Api/
  Program.cs                 настройка приложения
  Domain/                    сущности и правила валидации
  Data/                      DbContext, начальные данные
  Data/Migrations/           миграции EF Core
  Contracts/                 DTO запросов и ответов
  Endpoints/                 Minimal API: техника, каталог и словарь типов
  Infrastructure/            настройки и ответы об ошибках
  wwwroot/                   клиент на DevExtreme (index.html, js/app.js, css/site.css)
tests/ComputerEquipment.Api.Tests/  юнит-тесты (xUnit)
```

## Замечания

- DevExtreme подключается с CDN. Без коммерческой лицензии библиотека показывает предупреждение об ознакомительной версии — на работу это не влияет.
- Цвета и шрифты интерфейса вынесены в CSS-переменные в начале `wwwroot/css/site.css`.
